# txt2voice 业务架构

> 更新日期：2026-03-29

## 1. 产品定位

txt2voice 面向“把长文本稳定生产为可交付有声内容”的内部生产场景。它不是单次文本朗读工具，而是一个带流程编排、角色管理、音频质检、人工复核和任务运维的有声书工作台。

产品关注的核心问题：

- 如何把原始书稿稳定切成可处理的章节与段落
- 如何把段落变成可编辑、可追踪的结构化台本
- 如何把角色、Speaker、Voice 和多 Provider 音频能力绑定起来
- 如何在批量生成音频后建立质检、复核、重生和最终交付闭环

## 2. 业务角色

| 角色 | 主要职责 | 主要工作台 |
| --- | --- | --- |
| 内容运营 | 上传书稿、检查章节与段落切分、触发流程 | 书籍管理、书籍详情 |
| 台本运营 | 查看脚本结果、做局部重生、修正失败段 | 高级台本工作台、复核工作台 |
| 角色 / 声音运营 | 维护角色资料、别名、Speaker 与 Voice 绑定 | 角色管理、高级音频工作台 |
| 音频运营 | 配置 Provider、批量生成音频、合并试听 | 高级音频工作台、播放页 |
| 质检运营 | 运行 QC、处理人工复核、批量重生、解决告警 | 复核工作台、SLO 看板 |
| 平台运维 | 观察任务、恢复失败任务、维护派单策略与远端服务 | 任务中心、`qc/*`、`slo/*`、远端 TTS 栈 |

## 3. 核心业务对象

| 业务对象 | 含义 |
| --- | --- |
| 书籍 `Book` | 整个生产单元，承载状态、统计、任务与产物归属 |
| 章节 `Chapter` | 书籍的业务拆分单位，支持章节级处理与交付 |
| 段落 `TextSegment` | 台本生产的最小上游输入 |
| 角色 `CharacterProfile` | 人物、旁白等说话实体的标准档案 |
| 台词 `ScriptSentence` | 最终进入 TTS 的结构化句子 |
| Voice / Speaker 绑定 | 把业务角色映射到具体语音资产与引擎能力 |
| 音频 `AudioFile` / `SynthesisAttempt` | 音频产物与生成尝试记录 |
| 质检结果 `QualityCheckResult` | 自动质量判断结果 |
| 复核项 `ManualReviewItem` | 需要人工处理的问题单 |
| 任务 `ProcessingTask` | 用户可见的执行进度对象 |

## 4. 端到端业务流程

| 阶段 | 业务目标 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 书籍接入 | 建立新的生产对象 | `.txt` / `.md` 文件 | `Book` |
| 文本结构化 | 把原始书稿切成章节与段落 | 书稿文本 | `Chapter`、`TextSegment` |
| 台本生产 | 生成角色、说话人、情绪、语气、旁白结构 | `TextSegment` | `CharacterProfile`、`ScriptSentence` |
| 角色与声音配置 | 让业务角色拥有可用声音资产 | 角色档案、Voice / Speaker 库 | 绑定关系 |
| 音频生产 | 生成单句音频并按章节汇总 | `ScriptSentence`、角色绑定 | `AudioFile`、`SynthesisAttempt` |
| 自动质检 | 发现语义、时长、连续性、说话人漂移等问题 | 音频与台本 | `QualityCheckResult` |
| 人工复核 | 处理自动链路不能闭环的问题 | 质检结果、失败段、音频样本 | `ManualReviewItem` 的解决结果 |
| 最终组装 | 章节合并或全书收口 | 已通过质检或已复核的数据 | 可播放 / 可下载产物 |

## 5. 两种业务运行模式

### 5.1 分步模式

适合人工精细控制：

1. 上传书稿
2. 先检查章节与段落
3. 生成台本
4. 配置角色和声音
5. 生成音频
6. 跑质检与人工复核
7. 合并与交付

### 5.2 Auto Pipeline 模式

适合批量生产：

1. 触发自动编排
2. 系统串行执行文本处理、台本生产、音频生成、质检
3. 如无问题，直接进入最终收口
4. 如出现问题，把书籍推进到人工复核待处理状态

## 6. 主要业务工作台

### 6.1 书籍管理

页面：`/`

职责：

- 上传书稿
- 查看书籍列表与状态
- 进入具体书籍工作流

### 6.2 书籍详情

页面：`/books/[id]`

职责：

- 查看当前书籍总体状态、章节进度和产物统计
- 快速进入角色、台本、音频、质检工作台
- 发起全书台本生成

### 6.3 高级台本工作台

页面：`/books/[id]/studio/script`

职责：

- 查看分段结果与处理状态
- 做增量处理、局部重生、失败段修复
- 将自动结果与人工修正衔接起来

### 6.4 角色管理

页面：`/books/[id]/characters`

职责：

- 创建 / 编辑角色
- 从台本反向抽取角色
- 绑定 Speaker 与后续音频工作台联动

### 6.5 高级音频工作台

页面：`/books/[id]/studio/audio`

职责：

- 选择 Provider
- 维护角色与 Voice 的映射
- 配置批量参数、跳过策略、自动合并
- 触发批量音频生成

### 6.6 复核工作台

页面：`/books/[id]/review`

职责：

- 查看 `pending` / `reprocessing` / `resolved` / `rejected` 的复核项
- 按问题类型、优先级、推荐动作筛选
- 批量重生、批量解决、脚本编辑
- 查看 SLO 看板、派单事件和最近重生任务

### 6.7 任务中心

页面：`/tasks`

职责：

- 观察文本、台本、音频、质检、自动编排任务
- 查看子任务摘要与 Provider 指标
- 使用 replay token 重试失败任务

## 7. 业务状态流转

### 7.1 书籍状态

主状态集合：

`uploaded -> processing -> processed -> generating_script -> script_generated -> generating_audio -> quality_checking -> manual_review_pending -> assembling_audio -> completed`

补充分支：

- `completed_with_errors`：音频阶段有失败，但流程仍完成
- `error`：流程异常中断

这条状态机体现的是“生产视角”而不是“技术调用视角”。用户关心的是一本书现在处于哪个业务阶段，而不是某个函数执行到了哪一行。

### 7.2 复核项状态

`pending -> reprocessing -> resolved | rejected`

含义：

- `pending`：等待人工处理
- `reprocessing`：已经派发给脚本或音频重生链路
- `resolved`：问题已被处理并确认结束
- `rejected`：本轮重生或处理未通过，需要保留问题记录

## 8. 业务闭环

txt2voice 的关键不是“能生成”，而是“生成失败后仍然能收敛”。

闭环如下：

1. 自动生成台本或音频
2. 质检发现问题并写入 `QualityCheckResult`
3. 系统按规则生成 `ManualReviewItem`
4. 运营在复核工作台处理，可能触发脚本重生或音频重生
5. 结果重新进入质检或同步阶段
6. 若 backlog 清空，系统进入最终组装；若仍有问题，继续留在复核队列
7. SLO、派单策略与告警系统持续监控这条闭环是否退化

这意味着人工复核不是异常旁路，而是产品正式能力。

## 9. 当前业务边界

当前项目已经覆盖：

- 书籍接入与结构化处理
- 台本生成与角色管理
- 多 Provider 音频生成
- 自动质检、人工复核、批量重生
- 任务运维与 SLO 监控

当前项目暂未显式建设的领域：

- 读者端消费产品形态
- 计费、订单、版权结算
- 多租户后台权限体系

因此，当前仓库更接近“有声书生产中台 / 内部工作台”，而不是对外分发平台。
