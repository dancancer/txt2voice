# Script Studio Workbench Redesign

日期：2026-04-23
状态：已完成
范围：`/books/[id]`、`/books/[id]/chapters/[chapterId]`、`/books/[id]/studio/script`

## 背景

当前书内生产链路被拆散在多个页面中：

- `书籍详情` 负责入口分发
- `章节详情` 负责原文 / 台本 / 音频浏览
- `高级台本` 负责真正的生产操作

这导致用户需要在“看信息”和“做操作”之间反复跳转，形成双入口与双心智。

## 问题定义

当前结构的核心问题不是章节详情功能太少，而是职责切分错误：

1. 章节详情承载了浏览信息，但缺少完整操作闭环
2. 高级台本具备主要操作能力，却没有成为默认工作台
3. 书内关键任务被拆成两条路径：
   - 章节详情看内容
   - 高级台本做动作
4. 用户无法稳定形成“书内所有生产动作都去哪里做”的心智

## 设计目标

将 `高级台本` 升级为 `书籍生产工作台`，成为书内默认主工作区。

工作台应覆盖除全局设置之外的大部分书内操作：

- 查看章节与段落结构
- 查看原文
- 生成 / 重生成台本
- 编辑句级台本
- 生成句级 / 段级 / 章节 / 全书音频
- 查看失败任务与复核入口
- 快速进入角色处理

仅保留以下全局能力在工作台外：

- `LLM 设置`
- `说话人库 / 语音库`
- 高级音频参数调优

## 设计原则

基于 `.impeccable.md`，本次改造遵循：

1. `light-first`，保持生产控制台心智，不做展示型大屏
2. 信息密度优先于装饰，状态与动作前置
3. 单页完成主要任务，不让用户在章节详情和高级台本之间来回切换
4. 移动端不删核心能力，只改变布局
5. 先收拢入口，再补齐章级与段级体验，不做一次性重写

## 目标信息架构

### 一、书级

工作台首页承担整书级调度：

- 整书进度
- 待处理章节
- 最近失败任务
- 全书台本生成
- 全书音频生成
- 增量处理与指定段落重生

### 二、章级

章级视图替代旧章节详情，最终应包含：

- `总览`
- `原文`
- `段落`
- `章节音频`
- `异常`

### 三、段级

段级视图作为最细操作面，最终应包含：

- 当前段落原文
- 句级台本表
- 句级音频状态与试听
- 当前段落重生成
- 当前段落音频生成
- 当前段落失败复核入口

## 目标交互路径

主链路统一为：

`首页 -> 书籍详情 -> 书籍生产工作台 -> 章节 -> 段落 -> 编辑 / 生成 / 复核`

旧链路：

`书籍详情 -> 章节详情 -> 高级台本`

应逐步退役。

## 路由策略

### 工作台主入口

`/books/[id]/studio/script`

通过 URL 节点参数承载当前上下文：

- `book`
- `chapter:<chapterId>`
- `segment:<segmentId>`

### 兼容策略

旧路由 `/books/[id]/chapters/[chapterId]` 保留一段时间，但只负责重定向到：

`/books/[id]/studio/script?node=chapter:<chapterId>`

## 分阶段实施

### Phase 1：入口收拢

目标：

- 为工作台引入 URL 节点定位能力
- 让书籍详情里的章节入口统一跳到工作台
- 将旧章节详情页降级为兼容跳转壳页

验收标准：

- 刷新工作台后仍能回到当前章节或段落
- 书籍详情点击章节不再进入旧章节详情
- 旧章节详情链接仍可访问，但会跳转到工作台

### Phase 2：章级工作台替代章节详情

目标：

- 在工作台中补齐章级 `总览 / 原文 / 段落 / 异常`
- 将章节详情原本承载的信息搬入工作台

验收标准：

- 用户不需要离开工作台即可完成章节级浏览与操作
- 原文、段落状态、失败入口集中在章级视图

### Phase 3：段级闭环增强

目标：

- 补齐段级原文卡
- 句级试听与音频状态前置
- 角色快速处理内嵌

验收标准：

- 单段可以独立完成查看、编辑、生成和复核跳转

### Phase 4：书级工作台首页重构

目标：

- 将“请选择章节”替换为整书进度与待办工作台

验收标准：

- 用户进入工作台首页即可知道下一步应该处理什么
