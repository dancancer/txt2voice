# Task Round 2026-03-08 Phase 1 Round 1

## 基本信息

- 日期：2026-03-08
- 轮次：Phase 1 / Round 1
- 阶段：阶段 1：原文 -> 台本 正确性重建
- 分支：codex/phase-1-script-correctness
- 负责人：Codex

## 本轮目标

- 为台本生成链路补上第一层确定性守门：收紧 LLM 契约、阻断明显失真结果、补齐针对已知回归样例的测试。

## 本轮范围

- 收紧段落级台本生成 prompt，要求逐句映射、禁止改写、补充原文切片回溯字段。
- 在段落落库前引入脚本校验器，拦截漏抽、重抽、改写和顺序漂移。
- 调整段落映射逻辑，优先使用可追溯的原文切片，避免把 LLM 改写文本直接写入台本。
- 为高风险文本切段增加基础风险画像，优先缩小对白密集内容的分段粒度。
- 增加针对漏内容、重复对白、旁白/对白混抽、长段漂移的回归测试。

## 本轮不做的事

- 不处理 TTS provider 并发与补跑策略。
- 不改人工复核工作台 UI。
- 不在本轮引入完整 Script QC 任务编排或新的质检报表。

## 背景与问题分析

- 当前台本生成把文本内容本身交给 LLM 自由输出，导致改写、压缩和重复抽取没有确定性约束。
- 现有链路只修 JSON 语法，不校验语义保真；一旦 LLM 少抽或重抽，结果仍会落库污染后续音频与质检。
- 现有分段主要受长度控制，对对白密集段不够保守，长段更容易触发漂移。

## 关键假设

- 在段落级返回精确 `sourceText` 切片后，可以用顺序匹配构建一层足够便宜且稳定的守门校验。
- 让最终落库文本优先回落到 `sourceText`，比继续相信 LLM 生成文本更符合“原文保真”目标。
- 先做基础风险画像和收紧分段粒度，能在不重写分段器的前提下先降低高风险段的漂移概率。

## 执行计划

1. 收紧 prompt 和返回契约，要求逐条输出可追溯原文切片。
2. 增加段落级 Script Validator，并在 `processSegment` 中拦截失真结果。
3. 调整映射与分段策略，补齐对应单测与回归样例。

## 验收标准

- 校验失败的段落不再直接生成 `script_sentences`。
- 合法台本行的文本内容来自原文切片，而不是 LLM 改写结果。
- 新增测试能覆盖漏内容、重复对白、对白/旁白混抽、长段漂移四类问题。

## 本轮代码质检计划

- 工具：`pnpm --filter web test -- --runInBand --testPathPatterns=script-generator|text-processor|audiobook-regression`
- 计划执行时机：代码完成后立即执行
- 通过标准：新增和受影响测试全部通过

## 风险与回滚点

- 如果 `sourceText` 契约对现有模型过于严格，失败率可能短期升高；可回滚到仅记录校验结果、不阻断落库的实现。
- 分段粒度收紧会增加段落数与调用次数，需要观察后续成本变化。
